# Stage 3 — reconnect seat ownership

Protocol version 9 replaces nickname/peer-ID recovery with a random 256-bit client credential. Host stores it privately against the seat object; only the joining client's hello carries it. No credential is added to NetSeat, lobby broadcasts, game snapshots, saves or PlayerPrefs. An active seat cannot be claimed again, and original bots/public seats have no credential. Lobby removal/disconnect removes the reservation; in-game disconnect keeps the seat and credential while a bot plays.

The application retains credentials in memory per local profile object, current platform account and exact destination (LAN address, Steam lobby, or UGS code/ID). Returning using the same profile, account and connection route in the same application instance can reclaim the seat even if the nickname or peer ID changes. Restarting the application, switching profile/account, or using a different address/UGS join route cannot reclaim the old seat. This is a deliberate conservative limit; not durable authenticated recovery. TCP is plaintext, so the bearer credential does not protect against interception or malicious hosts; no claim of secure Internet identity. Upgrade all multiplayer participants together; v8 and v9 cannot join each other.

Tests: existing bot takeover/rejoin test now uses the credential and changed nickname; five new loopback tests plus six credential/cache cases. Verify LAN/Steam/UGS actual reconnect accessibility, same route, wrong nickname/credential, bot progression, no secret in broadcast payload, app restart behavior. Native lobby/relay availability and encryption are unchanged. No server deployment, rules, or save format changes.
